## 1. What DSpine is
A DFlash-style parallel block drafter: 5 layers, block 16, one backbone pass per round. The paper's diagnosis (probing the official Qwen3-8B DFlash drafter) is that independent per-position choices give inconsistent blocks. Prior fixes (Domino, DSpark) add a serial head after the backbone. DSpine instead passes a gated message from position t-1 to position t after every layer. The conditioning chain therefore builds over depth while positions still update in parallel.

## 2. Architecture (from paper HTML; Qwen3-8B drafter)
- Base: 5 transformer layers, hidden 4096. Target hidden states from layers {1, 9, 17, 25, 33} are fused and fed as K/V context into every drafter layer, as in DFlash. The target's embedding and LM head are shared and frozen.
- Attention: block-causal in all layers. Position t sees target context plus block positions 0..t. DFlash uses bidirectional attention inside the block. This is a real change in the base drafter, separate from ACI.
- Adjacent Causal Injection (ACI), after each layer l with hidden u:
  - Transfer projection z = f_l(u) = sqrt(r) * normalize(R_l u). R_l is learned per layer, r = 1024.
  - Gate g = sigmoid(G_q z_t + G_p z_{t-1} + b).
  - Message m = A z_{t-1}, with A shared across layers.
  - Write h_t = u_t + RMS(u_t) * W_l (g * m), with W_l per layer.
  - All messages use pre-update features, so every position injects in parallel. The anchor (position 0) is unchanged.
  - W_l, G_p and b are zero-initialised, so the model starts as the identity (plain DFlash-like).
  - Overhead is about 33M params (about 3% of the backbone).
- Unified transfer space: take the LM head, row-normalise it, centre it by the vocab mean, PCA-whiten, keep the top r = 1024 directions, row-normalise to get a fixed table C. Undecided predecessors send a predicted feature through f_l. Decoded tokens send sqrt(r) * C[token] through the same pathway.
- Predecessor-conditioned decoding ("last-write refinement"): the final layer gives top-K (K = 16) candidates per position. For each candidate at t-1, the final-layer write is redone from the cached pre-injection state, with the candidate's C embedding substituted for the predicted feature. A transition cache scores all K^2 candidate pairs per transition in one parallel pass, and selection is a left-to-right lookup. There is no new head module.
- Sliding window: the PAPER DOES NOT MENTION ONE. The README says the Qwen3.8-27B setup uses block 16 and an 8K sliding window. Treat the window as a serving/inference config for the 27B model, not part of the published method. UNCERTAIN.

## 3. Training recipe (paper)
- Data: ShareGPT prompts, responses regenerated by the target (thinking off). The same data is used for all baselines. Note the README's table says Open-PerfectBlend. See the section 5 discrepancy.
- Per sequence: 512 anchors, 1 anchor + 15 candidates, max len 3072, global batch 112 sequences, 6 epochs (3,655 steps).
- AdamW, no weight decay, peak LR 6e-4, 4% linear warmup (146 steps), cosine to 0, grad clip 1.0.
- L = L_dist + lambda * L_emb.
  - L_dist = sum_i w_i [ -alpha log q_i(y_i) + (1-alpha) ||q_i - p_i||_1 ], alpha = 0.1. q is the drafter and p is the target distribution. It is applied to both the backbone output and the refinement output (top-K, renormalised). The two have equal weight.
  - Position weight w_i = exp(-(t_i - 1)/gamma), gamma = 7.
  - L_emb = sum_layers sum_i w_i [1 - cos(f_l(post-injection state), C[y_i])]. This is layer-wise supervision toward the correct token's output embedding.
  - lambda = beta_t * stopgrad(CE_backbone). beta_t ramps 0 to 0.5 over the first 146 steps.
- Refinement masking: CE only where the true token is in the K candidates. The L1 term only where a candidate holds more than 1e-4 of target mass.
- Correct-predecessor curriculum: per block, with probability p, layers 1-3 get the TRUE predecessor embedding. p = 0.5 for the first 1/6 of training, then linear decay to 0 at 1/3.
- Baselines were trained on the same data with the same block size, 5 layers, 6 epochs, global batch and LR schedule. Per-baseline hyperparameters are not given.

Comparability caveats vs our DFlash/DFlash2 benchmarks:
- Block size 16 is used everywhere, but the serving runs use 15 draft tokens per round.
- Baselines are retrained by the DSpine authors on one dataset and a 6-epoch budget, so they are not the released DFlash/DFlash2 weights. Absolute tau differs strongly from released checkpoints (z-lab DFlash on its own data).

- Thinking is disabled in the data. Reasoning-mode accept lengths may differ.

## 6. Ablations and what matters
Table 3 variants were trained 3 epochs (1,827 steps), shorter than the main runs.
- Module ablation (tau, 8B, full / no refinement / no refinement and no injection):
  - MATH500: 5.49 / 5.11 / 4.93
  - MBPP: 4.98 / 4.65 / 4.54
  - MT-Bench: 4.11 / 3.82 / 3.67
- The last-write refinement is worth more (-6.6 to -7.1%) than ACI injection (a further -2 to -4%).
- The "no refinement and no injection" row still beats DFlash (3.77 on its own setup, though not directly comparable), which hints that causal mask, loss and layer supervision matter. This is an inference, not stated.
- Supervision target (tau, none / per-layer token CE / embedding cosine): MATH500 3.75 / 3.67 / 3.85, MBPP 3.48 / 3.40 / 3.63, MT-Bench 2.91 / 2.84 / 2.99. Per-layer token CE hurts. Cosine alignment into the whitened output-embedding space helps by about 3-4%.
- Probe findings (motivation, from the official DFlash drafter):
  - Early positions are decodable at shallow depth.
  - Giving the correct prefix from an early layer raises consecutive-correct tokens by 6.7% relative.
  - Injecting the same number of layers earlier raises the gain from 1.2% to 4.3%.
  - Swapping the correct predecessor for the draft prediction costs 31.8 points of successor accuracy.
  - Supplying the correct predecessor earlier rather than later gains 14.8 points.
- No ablation was found for block size, window, K, r, curriculum or the gate. Unknown whether these were tested. The project page says it has no formal ablation table, so the paper tables above are the only source.

## 7. DSpark dynamic verification, ReplaySSM, hybrid models
- DSpark (DeepSeek and PKU, arXiv 2607.05147; code in DeepSpec): a parallel draft backbone plus a light Markov head and a confidence head. Per request, it chooses the verification length from estimated prefix survival probabilities and an engine-specific throughput profile. The aim is to verify more tokens when the GPU is idle and fewer at high load. Verification stays lossless via rejection sampling. Details come from secondary summaries; the paper was not read.
- In DSpine's 27B setup, a draft block of 16 is not always fully verified. The README says SPS tuning picks a uniform width for batch sizes 1-7 and a total budget at batch 8, where verification allocation follows draft confidence. Default without a table is the full verify16. Note DSpine has no confidence head in the paper, so what supplies "draft confidence" for DSpine is UNCERTAIN (maybe the top-K probabilities).
- docs/sps_tuning.md: `scripts/tune_sps.py --requests prefixes.jsonl --output sps.json -- <sglang serve cmd>`. Prefixes are tokenized `input_ids` plus `sampling_params`. It needs at least 8 distinct prefixes and tuning is separate for greedy and sampling. It sweeps widths {4, 8, 12, 16} at batch sizes 1-8, with a warmup and 3 timed repetitions each. Score is the median of total output tokens over request wall time, which includes prefill. Use with `--speculative-dspark-sps-table-path sps.json`. Retune per GPU, model, runtime and workload.
- ReplaySSM (Johnny-Liou, vLLM fork with kernels for Mamba2 and Gated DeltaNet): SSM state is stored as a checkpoint plus a bounded buffer (length 16) of recent inputs. Outputs are computed without writing state, and periodic flushes fold the buffer into the checkpoint. Rejected speculative inputs are discarded by moving a buffer pointer, with no intermediate recurrent states materialized. The repo says flushes roughly halve state memory traffic.
- Why it is needed for Qwen3.8 (hybrid GatedDeltaNet): recurrent state cannot be rolled back by truncating a KV cache. The usual approach saves per-token states or recomputes, which is expensive. ReplaySSM makes accept/reject cheap. This reading is my inference from the repo text; the repo page itself does not explain the hybrid case. The README's 27B command uses `--enable-linear-replayssm-spec`, triton linear-attn backend, fp32 mamba SSM dtype, 131072 context, single GPU, up to 8 concurrent requests.
- The ReplaySSM repo's vLLM fork vs DSpine's SGLang flag: the integration path is unclear. UNCERTAIN.

## 9. What to steal / what to test
1. Run the released Qwen3-8B-DSpine-b16 against DFlash/DFlash2 in our harness, same prompts, same block and verify width, to settle the paper-vs-README gap (4.8 vs 7.8).
2. Port ACI as a small module on our DFlash drafter, zero-initialised so it starts as identity. Cost is about 3% params and under 0.15 ms per round.
3. Test the block-causal mask alone (no ACI) as a free ablation. DSpine never isolates it.
4. Add layer-wise cosine alignment to the whitened output-embedding table (r=1024). Avoid per-layer token CE.
5. Add last-write refinement with a K=16 transition cache. It was the largest single ablation gain (6.6-7.1%).
6. Copy the training schedule: 512 anchors/seq, w_i = exp(-(t-1)/7), alpha=0.1 CE+L1 mix, and the correct-predecessor curriculum.
7. For recursive/stacked drafters: use the predicted-feature-through-shared-transfer-space idea to pass a stage-1 draft feature to a stage-2 drafter, instead of passing tokens only.
8. Evaluate DSpark-style dynamic verify width. Run `tune_sps.py` per GPU, since verification is 72-76% of round time and a narrower verify at high concurrency should pay off.
9. For hybrid GDN targets (Qwen3.8): any spec decoder needs cheap recurrent-state rollback, so look at ReplaySSM before choosing an engine.
10. Compare fairly: same data, same epochs, thinking on and off, report tau and tok/s at concurrency 1-32, and record the GPU model (the paper omits it).
